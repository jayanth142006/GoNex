# GoNex API Reference

This is the API contract between GoNex and the CryptoNet frontend. To integrate, the frontend needs only the **GoNex base URL** and this document. It never talks to an LLM provider directly, and it doesn't need any AI logic of its own.

```text
GONEX_BASE_URL = https://<your-service>.onrender.com   (or your custom domain, e.g. https://gonex.example.com)
```

All endpoints use HTTPS in production. Request and response bodies are JSON (`Content-Type: application/json`).

---

## `POST /api/chat`

Sends a user's message to GoNex and returns GoNex's reply.

### Request body

| Field            | Type   | Required | Notes |
|------------------|--------|----------|-------|
| `message`        | string | yes      | The user's message. Leading/trailing whitespace is trimmed. Must be 1–2000 characters (`MAX_MESSAGE_CHARS`). |
| `conversationId` | string | no       | The `conversationId` from a previous GoNex response. Omit it (or send `null`/`""`) to start a new conversation. |

```json
{
  "message": "How does CryptoNet work?",
  "conversationId": "3f1c2a4e-8b7d-4c1e-9a55-2d6f0e7b9c10"
}
```

### Response `200 OK`

| Field            | Type   | Notes |
|------------------|--------|-------|
| `reply`          | string | GoNex's answer. Text with light Markdown: `**bold**`, `-` bullets, `1.` numbered steps and line breaks. Render it with a small, HTML-escaping Markdown renderer (see `renderMarkdown` in `public/app.js`), or show it as plain text with `white-space: pre-wrap`. |
| `conversationId` | string | Always returned. Send it with the user's next message to keep the conversation going. |

```json
{
  "reply": "CryptoNet lets a requester create a payment request for an INR amount and lock the matching DAI in a smart contract. A resolver then pays the INR via UPI, submits the 12-digit UPI transaction reference, and the contract releases the DAI (plus the ETH payer fee) to the resolver.",
  "conversationId": "3f1c2a4e-8b7d-4c1e-9a55-2d6f0e7b9c10"
}
```

### Conversation behaviour
- GoNex remembers the most recent messages of a conversation (default: last 8 messages) for `CONVERSATION_TTL_SECONDS` (default: 1 hour) after the last message.
- Conversation IDs are generated by the server. If you send an ID that has expired or is unknown, GoNex starts a fresh conversation and returns a **new** `conversationId`. Always store the `conversationId` from the latest response.
- To give the user a "New chat" button, just stop sending the old `conversationId`.

## `GET /` (built-in chat UI)

GoNex also serves a ready-made chat page at the base URL, `{GONEX_BASE_URL}/`. It talks to `/api/chat` on the same origin. Use it for testing and demos, or as a reference implementation for the CryptoNet chat window (`public/index.html`, `public/app.js`, `public/styles.css`). Set `SERVE_WEB_UI=false` to turn it off for an API-only deployment.

## `GET /health`

Liveness check. It is not rate limited.

```json
{ "status": "ok" }
```

## Errors

Every error response has the same shape:

```json
{ "error": "Human-readable, safe message." }
```

Error responses never include stack traces, prompts, provider names, API keys or infrastructure details.

| Status | When | Example `error` | Suggested frontend handling |
|--------|------|-----------------|-----------------------------|
| `400` | Missing or invalid `message`, invalid `conversationId`, malformed JSON | `message is required and must be a non-empty string of at most 2000 characters.` | Show a validation hint; don't retry unchanged. |
| `404` | Unknown route | `Not found.` | Check the URL. |
| `413` | Request body over 16 KB | `Request body is too large.` | Ask the user to shorten the message. |
| `415` | `Content-Type` isn't `application/json` | `Content-Type must be application/json.` | Fix the request header. |
| `429` | Rate limit exceeded (default 20 requests/minute per IP) | `Too many requests. Please slow down and try again later.` | Read the `Retry-After` header (seconds) and retry after that. |
| `500` | Unexpected server error | `Unable to process the request.` | Show a generic error and let the user retry. |
| `503` | AI service temporarily unavailable (provider down, timed out or overloaded) | `GoNex is temporarily unavailable. Please try again shortly.` | Show a "try again shortly" message and allow a retry. |

`401`/`403` are not used, because the API has no authentication. See *Security notes* below.

Rate-limit headers are included on responses: `x-ratelimit-limit`, `x-ratelimit-remaining`, `x-ratelimit-reset`, and `retry-after` on a 429.

## CORS

Only origins listed in the server's `ALLOWED_ORIGINS` environment variable get CORS headers. Allowed methods are `GET`, `POST` and `OPTIONS`, and the allowed request header is `Content-Type`. If the frontend sees a CORS error in the browser, ask the backend owner to add the frontend's exact origin (scheme + host + port, e.g. `https://app.cryptonet.example`) to `ALLOWED_ORIGINS`.

## Examples

### curl

```bash
BASE=https://<your-service>.onrender.com

curl -s $BASE/health

# New conversation
curl -s -X POST $BASE/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"What does COMMITTED mean?"}'

# Follow-up in the same conversation
curl -s -X POST $BASE/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"How long does the resolver have?","conversationId":"<id from previous response>"}'
```

### Browser (`fetch`)

```js
const GONEX_BASE_URL = import.meta.env.VITE_GONEX_BASE_URL; // e.g. https://gonex.example.com

let conversationId; // keep per chat session

export async function askGoNex(message) {
  const res = await fetch(`${GONEX_BASE_URL}/api/chat`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ message, conversationId }),
  });
  const data = await res.json().catch(() => ({}));
  if (!res.ok) {
    const retryAfter = res.headers.get('retry-after');
    throw Object.assign(new Error(data.error ?? 'Unable to reach GoNex.'), { status: res.status, retryAfter });
  }
  conversationId = data.conversationId;
  return data.reply;
}
```

Some replies take several seconds. Show a loading state, and use a client-side timeout of at least 60 seconds.

## Security notes

- GoNex is informational only. It cannot see user accounts, wallets, requests or transactions, and it never executes or verifies payments.
- GoNex never asks for private keys, seed phrases, UPI PINs or OTPs, and warns users who share them. The frontend shouldn't send such data either.
- The API has no client authentication. A key embedded in browser code would be public anyway. Abuse is limited instead by CORS allow-listing, per-IP rate limiting, request size and length limits, and server-side timeouts.
